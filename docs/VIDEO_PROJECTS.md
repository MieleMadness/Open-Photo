# Single-video editing projects (0.54.4)

Open a video and choose **New project from selected video**. The original player then uses the project's saved in/out points. Set trim values or use I/O markers; edit crop, quarter-turn rotation, flips, audio gain/mute, and canvas placement. Crop coordinates refer to the displayed, oriented source before additional project rotation. Free crops and centered square/landscape/portrait presets are available. Fit adds black borders; fill crops centrally. The default canvas accounts for source rotation.

Choose **Preview edits** to render the current saved instructions. This closes the original playback view while rendering/playing the derivative; **Back to source** returns to the original. Changing an edit cancels and invalidates the old result. Previews are SDR H.264/AAC, use square pixels, and fit within 960 by 540. Audio uses the first source track as stereo; extra tracks are disclosed. Native processing receives validated arguments and the same resource/cancellation controls as other preview jobs. Use the separate **Export video MP4** action to create a validated new file; see [VIDEO_EXPORT.md](VIDEO_EXPORT.md).

## Saving and recovery

Drafts autosave under the local Open-Photo application-data folder in `video-projects.sqlite`, independently of preferences and media caches. Each successful write increments a revision; stale writers are rejected. The queue serializes/coalesces changes and survives player unmounts. Window closure waits for pending saves; failures remain visible with retry or explicit close-without-saving. A failed session can save a recovery project copy or explicitly discard unsaved edits and reload its durable draft. SQLite keeps up to 20 previous documents per project. **Previous saves** lists them with available save number/time, title, trim range, and output dimensions. **Open previous save as new draft** creates a separate recovered draft; the current draft and its existing history remain unchanged. **Return to previous draft** saves pending work and reopens the parent draft during the same editor session. Recovered drafts are also ordinary saved projects.

**Recent projects** lists the latest 30 drafts for the selected library. Select one after restart to resume the saved state. Undo/redo keeps up to 100 edits during the current session; current edit settings persist across restarts, undo stacks do not. Reset is itself undoable. Organizational photo/AI data is unaffected.

**Save project copy** writes a versioned JSON document to a new filename, using staged publication without overwrite. It contains one asset and one clip with stable IDs, exact source-time tick strings/time bases, edit settings, and canvas settings. It references the original source relative to the selected library and includes full SHA-256 identity; it does not embed video bytes. Keep the source and project copy backed up together. **Open project file** validates and imports a new local draft, preserving asset/clip identities while assigning a fresh project ID to avoid overwriting another draft.

## Source identity and relinking

Creating/opening/rendering verifies the source's full SHA-256 and length without loading the video into memory. Source timestamps and edit instructions remain separate from derived previews. Missing/moved/changed sources cannot produce a trusted preview. Use **Relink original video** to select an identical file inside the current library; byte-different replacements are rejected. To use genuinely changed footage, create a new project. Portable project paths resolve against the current library root, so importing a project copy into a moved library can recover without an absolute old path. Files outside the chosen library and traversal paths are rejected.

## Limits and remaining acceptance

Schema version 1 supports one asset/clip, a minimum 0.04-second kept range, videos up to two hours and 100 megapixels per frame, crops of at least 1% on each axis, audio gain 0–200%, and even output canvases up to 4096 pixels per edge / 16 megapixels. Canvas aspect is bounded to 32:1. Imported documents are limited to 1 MB and unsupported schema/fields are rejected. HDR rendering is unavailable pending tested tone mapping.

Selection is derived from approximate browser playback time, quantized into source ticks. Rendered preview/export video timing validation allows two average-frame durations, bounded between 5 and 100 ms. Tests additionally compare VFR frame timestamps within 1 ms, decoded color regions, and audio gain. Generated export tests now cover preview/export frames, geometry, and audio, including non-frame-grid trims and a 90-second VFR fixture. Browser selection remains approximate, and frame accuracy/synchronization with long real footage remains an installed-app acceptance gate.

Still required: installed Windows tests for restart recovery, window close during saves, copied real media, long paths/videos, unavailable drives, disk failures, and hardware behavior. Waveform UI and HDR tone mapping remain deferred. Export writes a new SDR MP4 and intentionally omits source subtitles/chapters/metadata.

Version 0.54.7 exposes UHD landscape/portrait and supported source-resolution canvases, alongside the existing 1080p and square choices. Source-resolution geometry accounts for pixel aspect and source rotation; imported canvases remain available. Export using Project canvas to keep that resolution, or choose the 1080p export limit to reduce it.

## Previous-save recovery (0.54.9)

The history list is newest first and shows the latest 20 stored prior autosaves, rather than every keystroke or the session undo stack. Saves created before this update remain usable but may have no recorded number/time; the interface labels that metadata as unavailable. Later saves record the original save revision and timestamp. Dates use the desktop user's local display settings.

Opening an earlier save first flushes pending edits and checks that no newer local autosave occurred since listing history. The backend separately checks the database revision returned with that list. Refresh the list after editing or after another window changes the draft. A refreshed list can branch an older save while the current editor has no unsaved changes, without overwriting the newer draft saved by the other window. The backend checks the selected library, project, snapshot, and source identity in a transaction before creating a fresh project ID. A snapshot pruned by newer saves is rejected explicitly. Recovery never writes over the current draft.

Recovered edits retain the current source relink path and metadata for the identical source asset. A missing or changed source is reported normally; recovery of project instructions does not replace or recreate media. Unicode recovered titles are shortened as necessary to fit the editor limit. New drafts begin their own autosave history and session undo stack. The original history remains bounded to 20 records.

History database migration is atomic and repeatable, preserves legacy documents, and rejects storage from a newer unsupported schema. This recovery feature is not a backup of the source media or of the entire application-data directory.

## Brightness and contrast (0.54.10)

**Video brightness** and **Video contrast** accept whole numbers from -100 to 100; zero is neutral. Commit a value by leaving its field or pressing Enter. Choose **Preview edits** to view the saved result; source playback continues to show the original. **Reset brightness and contrast** clears only these two adjustments and is undoable. Both settings autosave and travel with saved project copies and recovered drafts.

Preview and export use the same per-channel full-range RGB transform: `(channel - 127.5) × (1 + contrast/100) + 127.5 + 255 × brightness/100`, clipped to 0–255 and converted to the SDR output format. Positive brightness lifts the picture; positive contrast increases the difference from middle gray. At contrast -100 the picture becomes flat gray before brightness. Extreme settings can clip detail. These are basic adjustments on encoded SDR color, rather than HDR tone mapping or linear-light exposure controls. Padding is applied afterward, so fit borders remain black.

Neutral settings omit the RGB adjustment stage entirely. Existing project files, local drafts, and previous saves with missing adjustment fields load at zero and retain the original render graph. Current documents include the new fields; open those copies with 0.54.10 or newer. Earlier releases reject unknown fields rather than silently ignoring saved adjustments. HDR rendering remains explicitly unavailable.

## Video posters and playback failures (0.54.11)

Library thumbnails for MOV/MP4/M4V/AVI/MKV/WebM now use the bundled video decoder. They are not sent to the photo-image decoder or limited to 75 MB source files. The decoder reads source streams, returns only a PNG still through IPC, and caches it by canonical source path, byte length, modification time, engine version, and requested size. Posters are at most 640 pixels per edge and 2 MB; extraction is timed and concurrency is bounded. A separate player slot prevents a library thumbnail queue from delaying the selected video's poster. Originals remain unchanged. HDR poster conversion remains unavailable pending tested tone mapping.

Opening a standalone video automatically loads its player, still, controls, and filmstrip without an extra click. It does not start audio automatically. Embedded Live Photo motion retains its explicit Play action. The player uses the still as a poster while loading. Click Play to request playback of the original video. Native controls remain available if the browser requires another user gesture for audio playback. On original-format decode/unsupported errors (media codes 3/4), the app automatically attempts one compatible preview, retaining the source position. It does not repeat conversion if that preview fails. Network/stream-read errors (code 2) remain explicit because converting cannot repair a blocked stream. The manual compatible-preview action and Windows-player fallback remain available. HDR playback failures do not automatically request unsupported tone mapping. Existing proxy duration, size, and processing limits still apply; long or unsupported conversions can fail explicitly.

Report the media error number/message and whether compatible playback succeeds when diagnosing a blank player. Native thumbnail extraction can work even when WebView cannot decode the source codec; a poster alone does not prove successful playback. Installed-app testing of the reported file remains required.

Loaded media with zero video dimensions also triggers compatibility once: a browser can decode a file's audio while failing to expose its video track, without raising a normal media error. If the compatible result also lacks a video track, the player reports that failure instead of repeatedly converting.

Legacy migration also copies up to 20 previous saves per draft. Older revisions with no recorded date or revision keep that information unavailable; no historical dates are invented. Player trim markers update the selected timeline instance, and source-changing operations lock those markers until verification finishes. Reset selected clip restores its source interval/edits; Reset project canvas separately restores the default canvas.
