# Saved folders and uninstall behavior (0.54.12)

Open-Photo saves folder references, preferences, ratings, collections, AI indexes, reviewed names, and video drafts separately from the source media. A retained installation restores its active workspace and loads its folders on startup. Missing folders report scan errors instead of silently being removed. This is independent of Auto-sync, which controls later periodic/watcher updates.

The Library and Folders views list the source folders in the current workspace. **Remove from library** removes a folder reference from that workspace's view, saves the change, invalidates older scans/AI batches, and reloads remaining folders. It does not delete media, XMP sidecars, saved edits, or index records. Add the folder again to resume using it. If another added parent folder includes the same files, those files remain included through that parent. Other workspaces retain their own membership.

Uninstall keeps app data by default so upgrades/reinstallation can preserve work. Select **Delete the application data** in the new version's uninstaller for a clean local reset. This also removes local saved video drafts, ratings, virtual organization, person names, AI indexes, and preferences. Original media, exported copies/projects, and sidecars outside app-private storage are not removed.

The standard Tauri checkbox clears browser storage under the application identifier. The Open-Photo hook also removes its six known SQLite databases and their WAL/SHM/journal files under `%LOCALAPPDATA%/Open-Photo`, plus legacy model copies and preview caches. It does not read/traverse media-library paths and does not recursively remove that parent directory, which can also be an install location or contain other files. Updates always retain data. Cleanup failures are reported rather than silently claimed successful.

Silent uninstall retains data. `/PURGEAPPDATA=1` is explicit cleanup consent; `/UPDATE` takes precedence and preserves data even if both switches are present. The lifecycle test refuses to run on personal or persistent self-hosted profiles. On disposable GitHub-hosted Windows it installs the real package, verifies installed model hashes/inference, tests update and default retention, tests explicit cleanup, and checks that an unknown media sentinel survives. Checkbox presentation and general application GUI acceptance remain manual checks.
