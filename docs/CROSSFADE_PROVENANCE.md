# Experimental normalized-clip receipts

The test-only `crossfade_provenance::verify_ordered_receipts` gate checks a list of normalized media receipts against an existing saved video-sequence Snapshot, the exact ordered input MKV paths and the expected per-clip frame allocations. Each receipt contains its timeline clip ID, source asset ID, **previously saved source SHA-256**, normalized part path, part SHA-256 and expected frame count. It rejects missing/extra inputs, mismatched order, duplicate clip IDs or file paths, incorrect source identity, cancellation, and changed normalized bytes. A native sequence fixture exercises valid receipts, swapped parts, cancellation and a same-size normalized-part mutation.

**Critical trust boundary:** the current receipt struct is only a data-integrity contract. It cannot prove that the normalizer actually generated a particular MKV from that saved original, and caller-generated receipts must never be trusted. Future production integration must have the trusted normalizer mint receipts after processing each original, safely associate source handles and clip IDs, and keep output file ownership stable while the verifier and renderer use the same content. Until then, this gate is test-only; no production crossfade export/UI is enabled.
