# AI, media viewer and private vault roadmap

Requested October 30, 2026 against 0.56.21. The focused 0.56.22 implementation is recorded below; other groups remain planned. Preserve the existing A–J phases and shared editor architecture.

## Implementation checkpoint — 0.56.22

Implemented: compact Library search/filter/thumbnail controls; removed tips/tools/permanent editor opener; Edits navigation; folder/collection List/Tiles preferences; manual Sync with offline SQLite restoration and partial-failure retention; relocated duplicate/similar review and manual AI tools; 400ms automatic search with previous-result retention and stable media labels. Tile views use existing folder/collection information and icons; representative collection thumbnails remain optional future work.

Remaining: R0 signed Preview updates, R2 automatic AI indexing/dashboard/counters/folder exclusions, R3–R4 viewer work, R5–R6 vault and later F–J features. The specifications below describe the full intended behavior, including these outstanding groups.


## Findings and proposed direction

These findings come from source review and the reported behavior, not a new rendered visual audit. Reproduce the overlap in the installed app before choosing its precise layout fix.

| Before | After | Why |
| --- | --- | --- |
| `useUnifiedSearch.ts` debounces cached lookups but requires submit for semantic evidence; changing the query immediately drops the previous evidence. | Debounce the complete query, search automatically after typing stops, retain the previous completed view with a searching state. | Avoid a blank gallery while waiting for content matches. |
| `App.tsx` starts semantic/OCR/People indexing through separate manual actions. | One durable background coordinator starts eligible work when local AI is enabled. | An on/off setting should control the complete local indexing workflow. |
| Indexing summaries are transient; errors are accumulated as message strings. | Workspace counts and a durable, per-file failure list with retry. | Show what is complete, pending, skipped or failing across restarts. |
| Search tiles can replace their media label with “Image content.” | Keep **Image**, **Live image** or **Video** visible; show match reasons separately. | Media identity and the reason for a search match answer different questions. |
| Details uses a 510px drawer, a 220px still preview and generic settings-card styling for photo edits. | Give photo editing a full-width layout and use available window height for the preview. | Recover usable space without shrinking labels or controls. |
| Live motion is rendered outside the main still preview; fullscreen CSS hides most other details children. | Share one media stage that can switch a paired still to motion in either viewer size. | Live images must work in fullscreen without a second player or hidden motion area. |
| The shared video player can expose native controls plus extra transport/filmstrip UI. | A viewer-specific mode uses one player and its native controls. | Keep editing/timeline tools in the editor and avoid duplicate playback controls. |
| Fullscreen expands the details drawer and hides content with broad CSS selectors. | A dedicated viewer composition shares media/selection state and has an explicit, hideable library filmstrip. | Avoid accumulating hide/show exceptions in the drawer. |

Use the existing compact native application design, light/dark tokens, accent preferences and green section labels. Apply UI/UX Pro Max to layout/accessibility, Impeccable to hierarchy/states/spacing, and Emil design engineering to zoom, navigation, panel and filmstrip interactions. No unrelated visual rewrite.

## R0 — Preview builds update in place

- Current source supports only signed newer major stable releases (`N.0.0`); regular development installers have no configured updater public key. A successful CI installer upload is not yet a published update channel. See [UPDATES.md](UPDATES.md) for the current policy and the planned Preview extension.
- Add a separate **Preview** channel for deliberately published, signed development patch releases. Keep the Stable channel's existing major-only gate. Preview must not bypass signature verification, publish arbitrary CI artifacts automatically or expose signing keys to fork/untrusted pull-request builds.
- Provide a signed bootstrap Preview installer that keeps the same application identifier and data locations. Install it over the existing app, preserving workspace folders, projects, tags, preferences and local indexes. The currently installed build may require this one final manual upgrade because its updater is disabled or rejects preview versions. Do not promise that an old unsigned build can discover its own bootstrap update.
- In Settings → Updates, show installed version and selected channel with **Check for updates**, release notes, download progress and **Restart & install**. Preview installs use Preview by default; switching to Preview from Stable is explicit. Channel selection is separate from manual Library Sync and local AI indexing. Do not silently download/install updates or interrupt active work.
- Use a fixed HTTPS Preview manifest endpoint, proposed `releases/download/preview-channel/latest.json`, separate from `stable-channel`. Reference immutable versioned installer/signature assets. Validate version consistency and a strictly newer supported version under the selected channel's comparator; never downgrade automatically when changing channels. Preserve the current signature/version binding and download timeout behavior.
- Extend release tooling with a Preview publish workflow for a trusted maintained branch/exact commit whose required checks pass. Validate synchronized versions, build/sign the updater, test it, upload versioned assets, then update the Preview manifest last. An interrupted publication must leave the previous working manifest available. Keep private signing material outside source control and configure the trusted public key in the bootstrap app. Check actual signing setup before implementation; this plan does not assert keys/secrets are configured.
- Reuse active-export protection and revision-safe project flushing before restart. Cancelled downloads, failed saves, signature failures and failed installation remain recoverable without uninstalling or clearing app data. Version any necessary database migration and test preservation of existing data.
- Acceptance requires two genuinely signed short-test Preview versions: install the bootstrap, update in place to the next version, reopen saved work, verify bundled AI and data retention, and test wrong signatures, stable/preview isolation, already-current/offline states and active-work blocking. Mocked updater tests alone do not prove the channel works. Update release instructions/version policy when implemented; no release or key generation happens in this planning change.

## R1 — Search as typing stops

- **Collections view:** add **List / Tiles** to Collections, with the same open, rename and remove-collection actions in either presentation, including existing smart-collection behavior. Remember the choice per workspace independently of Browse folders and Library views; default to the current presentation when unset. List shows compact names/counts; Tiles may use bounded lazy representative thumbnails from current collection members, with a clear fallback for empty/unavailable collections. Preserve selection, sorting, filters and collection identities when switching. Removing a collection never removes its source media. Test long names, empty/offline states, keyboard access, preference persistence and equivalent manual/smart collection actions. Switching view must not trigger Sync or AI indexing.
- **Browse folders view:** add a labeled **List / Tiles** switch to the Browse folders section in Folders & Workspaces. Both presentations use the same folders, ordering, selection and open/remove actions. List uses compact rows with folder name/path and available status/count; Tiles uses compact folder cards with the same information and no invented preview/count data. Remember the chosen view per workspace, defaulting to the existing presentation when no preference is saved. Support keyboard navigation, accessible selected state, long paths, empty/loading/offline states and narrow windows. Changing view must not trigger Sync, AI indexing or any filesystem mutation. Keep this preference separate from the Library media grid/list setting; test persistence and equivalent actions in both folder views.
- **Manual library sync (latest feedback):** remove the Auto sync toggle and periodic background sync. Disable watcher-triggered rescans/reconciliation as well, so removing the timer does not leave hidden automatic syncing. Keep a clearly labeled **Sync** button in the compact Library toolbar, with progress, last-sync status and actionable errors; prevent concurrent duplicate runs. Opening a saved workspace restores its stored library snapshot rather than starting another filesystem scan. Explicitly adding a folder performs its initial import; later additions, changes and removals are reconciled only when the user clicks Sync. Preserve incomplete-scan safeguards, workspace ownership and original-media safety. Existing saved auto-sync preferences must not silently reactivate scanning. Test timer/watcher inactivity, manual reconciliation, startup restoration and safe failure/retry.
- Add **Edits** to the left navigation. It opens the video editor dashboard for creating/resuming workspace-owned projects; photos and videos still enter the same continuous editor. This is the requested entry point replacing the Library's permanent editor opener. Retain the top-left workspace dropdown and compact/collapsible navigation. The earlier rejection of a separate **Video Projects** architecture does not prohibit this explicitly requested Edits destination.
- **Library composition (latest feedback):** bring the media grid higher in the window. Keep the compact heading/green section label and workspace dropdown at the top left. Remove the permanent **Open video editor…** button from Library. Keep a contextual **Create video from selection…** action only when media is selected, plus the existing file-details Edit entry, so mixed-media editing remains accessible without occupying the default browsing toolbar.
- Put **Search library** in the toolbar position currently occupied by thumbnail zoom. Move **Thumbnail size** to a compact, right-aligned control immediately above the media grid. This is the Library thumbnail-size slider; the separate viewer wheel-zoom plan in R3 remains unchanged. On narrow windows, wrap intentionally without covering the first image row.
- Remove visible **search tips**, instructional search-help paragraphs and the entire **Search and library tools** disclosure from Library. Keep actionable query errors, loading, completed empty states and provider failures concise; avoid replacing the removed tools with another permanent banner. Preserve useful sort, media/rating filters and view controls in the compact toolbar or its overflow menu.
- Move **Find Exact Duplicates** and **Find Similar Photos** into a **Library cleanup** section of **Folders & Workspaces**, with their results/review there. These remain explicit, read-only actions; do not silently auto-delete duplicates or require AI for exact matching. Manual semantic/OCR/People indexing controls move into the AI dashboard as retry/rebuild actions, while normal indexing becomes automatic. Do not remove the underlying features merely to remove their Library controls.
- Use one committed query after approximately **400ms** idle for metadata, OCR, People and semantic results. Enter/Search runs immediately; Escape/clear restores browsing. Coalesce duplicate requests.
- Cancel superseded work and reject late responses after query, workspace, library snapshot or AI-setting changes. Reuse native cancellation and deterministic ranked results.
- Keep the last completed results visible, clearly marked as updating, until the new query is ready. Do not label old results as matches for the new query. Show “No matches” only after a completed search, with useful clear/filter actions.
- Metadata continues with AI off. A failed AI provider leaves valid metadata results visible with a bounded warning. Search must remain usable during background indexing; update matches incrementally, without refreshing on every indexed frame or restarting all inference.
- Remove the instruction to press Enter for image-content matches. Preserve query syntax, ratings/tags/folder filters, relevance ordering and workspace boundaries.
- Keep media type distinct from evidence: **Image**, **Live image**, **Video**. Pair Live images using existing verified pairing rules; ordinary videos remain Video. A live pair is one logical media item. “Visual match,” “Text match” or “Person match” can explain relevance separately, with times for video evidence.
- Reproduce and fix search-result overlap at the layout/measurement level: compact toolbar and necessary transient status/warnings occupy real rows; the virtualized gallery gets the remaining height. Recalculate its viewport when these rows wrap, resize or expand. Detailed indexing counters belong in the AI dashboard rather than a new always-visible Library row. Avoid fixed-height offsets and stacked positioning patches.
- Verify long filenames/reasons, many warnings, expanded tools, collapsed sidebar, light/dark, 800×580 and larger windows, and Windows text scaling. Loading and counts should be accessible without announcing each keystroke.

## R2 — AI starts when enabled, with visible progress

- Turning AI on schedules supported media already known to the active workspace's saved library snapshot. Already-enabled startup resumes outstanding known work without scanning folders. An explicit initial folder import or manual **Sync** makes added/changed files eligible for automatic AI processing; already-current model/pipeline results are skipped. Automatic AI processing does not re-enable filesystem watching, periodic sync or background discovery. Preserve the per-folder Don't index policy.
- Provide an **AI dashboard** reachable from Settings → Local AI. Use a compact folder table and progress/failure views rather than dashboard cards in Library. Show the workspace's registered folders, full path, inclusion policy, indexed/pending/failed totals and current activity. Keep excluded, unsupported and offline states distinct.
- Each folder has **Don't index** when included and **Index folder** when excluded. Persist this AI-only policy per workspace, defaulting new folders to included while AI is on. Excluding a folder leaves it visible and browsable in Library, with normal metadata indexing/search intact; it stops automatic semantic/OCR/People/video-AI work and excludes existing AI evidence from ordinary searches for that workspace. Explicit indexing/rebuild must also honor exclusions.
- Enforce folder policy in the native scheduler and query providers, not only by hiding buttons. Cancel/remove queued work for excluded descendants and stop running work at a safe boundary; late completion cannot make excluded AI evidence visible. Resolve nested/overlapping roots consistently: an excluded ancestor excludes its descendants until re-enabled. Scope policy to the current workspace so it does not silently change another workspace's settings or erase shared cached evidence.
- Keep local cached AI entries on exclusion by default, without using them in that workspace; offer separately labeled explicit cache clearing if needed. Re-enabling queues only missing/stale work. Excluded items do not inflate pending/failure counts; show their count separately. Removing a folder reference updates the dashboard without touching its media.
- A durable native job coordinator owns the queue, progress, cancellation and retries. React observes it rather than owning long-lived indexing loops. Reuse existing semantic/OCR/People services and model validation; do not create duplicate indexes or inference engines.
- Use bounded batches and a shared inference budget, prioritizing interactive search over background work. Stop scheduling on AI off; finish or cancel the current safe unit and retain completed entries. Workspace switching cannot leak jobs/results into another workspace. Record resumable work per workspace and prioritize the active one.
- Persist item identity, source freshness, provider/model version, state, attempt time and a bounded error reason. Replace an item's successful index transactionally; cancellation or failure must not leave a partial item marked complete. Missing models or unavailable services produce a clear paused/unavailable state, not thousands of per-file failures.
- Show counters in the AI dashboard and a concise summary in Local AI Settings: **Indexed / Pending / Failed**, plus **Excluded** and **Skipped or unsupported** when relevant. Do not reserve another Library header row for them. Counts refer to distinct media items for the current workspace, not embeddings, faces or video frames. Indicate partial completion and expose provider-specific details. Progress should not flicker as small batches finish.
- **View failures** opens a searchable list with filename, folder, media type, failed service, reason and last attempt. Offer Retry selected / Retry failed and reveal/open the original where available. Retries are explicit or bounded; never loop endlessly on corrupt files. Clearing a failure record never deletes media.
- AI off stops indexing and excludes AI evidence from search; existing local indexes remain until an explicit clear-index action. Source media is never changed. Vault media must never enter this normal queue.
- Test enable/startup/new-folder/change/resume, freshness/model updates, duplicate suppression, cancellation, restart, nested-folder exclusions, stale completions after exclusion, re-enable, cross-workspace policy/cache safety, search responsiveness, partial provider failure and accurate durable counts. Verify that Don't index never removes a folder from Library or disables ordinary metadata search.

## R3 — Details, image sizing, zoom and Live images

- Replace the generic settings-card row used by **Edit & Export** with an editor-specific grid. Fields use the available details width; the save action has its own footer row. At wide sizes, expand the details/edit surface appropriately; at narrow sizes, stack controls without overflow. Verify actual width constraints before changing them.
- Compute preview space from the current window and visible header/controls, rather than retaining a fixed 220px image box. Add modest inner padding, preserve aspect ratio and show the complete image by default. Increase stage height on taller windows while retaining access to editing/metadata controls. Do not crop merely to fill side margins.
- Share zoom/pan behavior between normal and fullscreen still previews: wheel/trackpad zoom while the pointer is over the stage, anchored near the pointer; bounded pan when enlarged; Fit, 100%, zoom in/out and reset alternatives. Wheel events elsewhere continue scrolling normally. At fit/minimum zoom, allow outward scrolling rather than trapping the details panel. Respect reduced motion and prevent runaway momentum/accidental page zoom.
- Reset or clamp the view when switching media, orientation or available stage size. Request larger image resolution only as needed with bounded decode/cache work. Viewer zoom never changes crop/edit/export data.
- For Live images, retain the still as the default and use an explicit play icon to show the paired motion in the same stage. Use the video element's controls; remove the extra motion filmstrip, duplicate play/skip/scrub controls and inspection-only transport clutter. Keep compatibility-preview fallback and useful playback errors.
- One playback owner: leaving motion, switching files, closing or locking pauses/releases it. Use explicit player modes rather than misusing `editorMode` to hide viewer controls.
- Test image orientation, portrait/panorama shapes, padding, window resizing, wheel boundaries, zoom/pan reset, draft preservation, native-only motion controls, unsupported playback and unchanged exports.

## R4 — A content-first fullscreen viewer

- Use nearly the entire window for media with small safe padding. A compact top overlay contains title/type, Fit/zoom, filmstrip toggle and Close; previous/next controls sit at the side edges, away from media and native playback controls. Controls remain available on focus and do not disappear during interaction.
- Keep details/editing as an explicit optional panel rather than reserving permanent width for metadata. Share selection, media loading, zoom, Live pairing and playback primitives with normal details; do not duplicate editor state or bypass preview/file protections.
- Add a bottom **library filmstrip**, distinct from video-frame thumbnails. It follows the currently visible Library's sort/filter order, includes images/live images/videos, marks the current item and supports click/keyboard navigation. Preserve Library scroll position when closing.
- A labeled Show/Hide filmstrip button remembers the preference. Hiding it returns its space to the stage. Use lazy thumbnails, bounded work and horizontal virtualization; keep the selected item in view without jumping the entire Library. No automatic audio or motion for neighboring thumbnails.
- Live images have a clear play icon and the same native-control motion mode as R3. Videos play in the shared stage. Switching items stops the prior decoder; source compatibility errors remain recoverable.
- Support Left/Right navigation, Escape, keyboard-accessible thumbnails and visible focus. Avoid intercepting editing-field keys or native player shortcuts. Subtle fast fades/panel movement explain changes; do not animate every thumbnail or media navigation.
- Verify both themes, minimum/large windows, high-DPI/text scaling, orientation changes, video aspect ratios, filmstrip visibility, search-result navigation and decoder/memory cleanup.

## R5–R6 — PIN-protected private vault

### Product behavior

- **Three rapid clicks on the app version** reveal the vault setup/unlock entry; repeated clicks must not create duplicate dialogs. Provide a keyboard/screen-reader equivalent on that same control without adding a permanent main-navigation tab. The hidden gesture is an entry point, not authentication.
- First use creates/confirms a PIN. Proposed default: at least six digits, with a longer passphrase option. Unlock and PIN change use a native authenticated service, with persisted attempt throttling/backoff and clear feedback. Do not store a raw PIN or unsalted fast hash in preferences.
- The private area opens only after unlocking. Lock explicitly and on app exit, workspace change and Windows session lock; proposed inactivity timeout is five minutes. Lock clears visible content and key references, stops playback and cancels vault jobs. Ordinary navigation must never reveal a locked item.
- Private entries, names, thumbnails and search/AI metadata stay outside normal Library, search, People, Memories, maps, recent projects, hover previews and the fullscreen filmstrip. Implement this as a data/access boundary, not a CSS filter. Normal indexes and logs must not contain vault paths or content.

### Storage and source safety

- Store encrypted media and sensitive metadata, using a vetted authenticated-encryption implementation and OS-protected key handling. PIN verification and key use belong in Rust. Authorize each vault operation with a short-lived unlock session; frontend visibility cannot grant file access.
- Default **Copy into Vault** preserves originals. Clearly state that any original left outside the vault is still accessible and is not protected by encrypting a copy. Never silently move/delete originals, and do not imply a vault copy hides every outside copy. A future explicit move/cleanup workflow requires separate confirmation, verified import and recovery design.
- Use staged writes and verify decryptability/integrity before publishing imports. Reject traversal/symlinks and untrusted destinations through the existing file-safety boundaries. Lock, cancellation, crash, no-space or a racing destination must not produce a reported-success corrupt import or modify a source.
- Avoid persistent plaintext previews, poster caches, exports, backups or FFmpeg scratch files. Design the playback/decryption bridge before supporting vault videos; decrypted data must have bounded lifetime and memory. Normal AI indexing is excluded initially. Exporting a decrypted copy, if supported, must be explicit and disclose that it leaves the vault.
- Decide the exact key format/library, Windows-account versus portable recovery, forgotten-PIN policy, backup/restore and crash-safe key rotation before R6. Proposed policy: no bypass PIN, no automatic wipe after failed attempts, and no deletion when reset is requested. OS-bound recovery/portability limitations must be explained before import. Do not label the vault secure until the storage/access review and tests pass.
- Test incorrect PIN/throttling/restart, lock/session expiry, direct-command access while locked, tampered ciphertext, traversal, crash/cancel/no-space imports, source preservation, exclusion from all normal caches/indexes and recovery/backup behavior. Use synthetic short media only.

## Completion gates and scope

Each implemented patch needs focused behavior tests, frontend/TypeScript/build and Rust checks appropriate to its changes, light/dark visual checks for affected screens, a synchronized patch release and documentation, then exact-commit GitHub Actions verification. Test source safety and player cleanup rather than only button presence. Short fixtures remain mandatory.

The original planning pass changed documentation only.
