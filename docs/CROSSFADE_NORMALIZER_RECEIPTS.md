# Test-only normalizer-minted crossfade provenance checkpoint

The native Windows sequence fixture now mints an ordered provenance receipt **inside its existing trusted normalized-clip production loop**, immediately after the real bundled FFmpeg produces and video-probe validates each MKV. The fixture first revalidates the saved original media using its stored source fingerprint, then records the corresponding saved clip ID, asset ID, saved SHA-256, normalized MKV path, normalized SHA-256 and allocated frame count.

Before the native crossfade graph consumes the MKVs, the fixture verifies every receipt in timeline order with the previously merged `crossfade_provenance::verify_ordered_receipts` gate. The fixture deliberately swaps part order and flips one byte in an already-normalized MKV to prove rejection, then restores that byte and proves the original receipt verifies again. The existing mixed-audio fixture still renders the graph with one audible source and one audio-less source after these checks.

**Security boundary:** this is a _test-only acceptance integration_, not a production interface or a complete authenticated provenance system. The experiment demonstrates where a future trusted normalizer should mint receipts and how the consumer verifies them. Real production integration must enforce stable source/normalized file handle ownership, avoid reparse-point/TOCTOU races, validate that source-to-part mapping is generated only by the trusted encoder, and prevent untrusted callers from constructing their own accepted receipts. No active user-facing crossfade path, saved project schema or editor UI changed.
